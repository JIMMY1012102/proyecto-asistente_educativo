# ADR-001 — Framework de aplicación

**Estado:** Aceptado  
**Fecha:** 2026-10-09

## Contexto

Los drivers principales son R1, R2, R3, R10 y R11. Los atributos prioritarios son rendimiento, seguridad y disponibilidad.

La aplicación debe ejecutarse sobre PHP 8.x y XAMPP, con MySQL/MariaDB como base de datos. La instalación concreta del framework sobre XAMPP queda marcada como **[VERIFICAR EN SEMANA 7]**.

## Alternativas evaluadas

### Laravel
**Ventajas**
- Framework completo y estructurado.
- Incluye herramientas para autenticación, validación y persistencia.

**Desventajas**
- Mayor complejidad inicial para el alcance académico actual.
- Puede introducir componentes que el proyecto todavía no necesita.

### CodeIgniter 4
**Ventajas**
- Arquitectura MVC clara.
- Menor complejidad para un proyecto web pequeño.
- Permite organizar controladores, modelos, vistas y servicios.

**Desventajas**
- Algunas capacidades requieren configuración explícita.
- Instalación y compatibilidad con XAMPP: **[VERIFICAR]**.

### PHP 8 con MVC propio
**Ventajas**
- Control total de la estructura.
- Menor dependencia de frameworks externos.

**Desventajas**
- Obliga a construir infraestructura básica.
- Aumenta el riesgo de errores de seguridad y mantenimiento.

## Decisión

Se adopta **CodeIgniter 4, versión estable vigente [VERIFICAR]**, usando un **monolito MVC en capas con renderizado en servidor**.

La decisión prioriza simplicidad, mantenibilidad y rapidez de implementación.

## Consecuencias

- La aplicación seguirá el patrón MVC.
- Los componentes deberán trazar a `requirements.md`.
- La interfaz será servida inicialmente desde el servidor.
- La integración futura con IA/MCP quedará como punto de extensión.

## Deuda aceptada

La instalación y configuración exacta de CodeIgniter 4 en XAMPP se comprobará antes de la semana 7.

## Criterio de reversión

Si CodeIgniter 4 no puede instalarse o ejecutar una ruta MVC mínima correctamente en XAMPP antes de la semana 7, se reconsiderará PHP 8 con MVC propio.
