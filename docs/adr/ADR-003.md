# ADR-003 — Estructura del repositorio y flujo de ramas

**Estado:** Aceptado  
**Fecha:** 2026-10-09

## Contexto

El equipo necesita trabajar sin modificar directamente la versión estable del proyecto.

La arquitectura y documentación deben quedar versionadas en GitHub y el trabajo de la sesión debe integrarse en `develop`.

## Alternativas evaluadas

### Trabajar directamente en main
Se descarta porque mezcla trabajo estable con cambios en progreso.

### Usar solo develop
Es simple, pero dificulta aislar cambios de varios integrantes.

### main + develop + feature-nombre
Permite separar versión estable, integración y tareas individuales.

## Decisión

Se adopta:

- `main`: versión estable.
- `develop`: integración.
- `feature-nombre`: tareas específicas.

Se utilizarán **Conventional Commits en español**.

Ejemplos:

- `docs: agregar arquitectura C4`
- `feat: agregar autenticacion`
- `fix: corregir validacion de roles`

Toda integración a `develop` deberá ser revisada por otro integrante.

## Consecuencias

- No se trabajará directamente sobre `main`.
- Las nuevas tareas usarán ramas `feature-*`.
- La arquitectura se integrará primero en `develop`.

## Deuda aceptada

La protección automática de ramas queda **[VERIFICAR]** según los permisos disponibles en GitHub.

## Criterio de reversión

Si el flujo genera conflictos frecuentes antes de la semana 7, se simplificará temporalmente a `develop` manteniendo revisión por pares.
